# 生成草稿恢复

## 目标

模型已经返回结构化试卷后，如果入库前校验或保存失败，不再次调用整卷生成模型。服务端保留短期恢复草稿，任务队列提供“处理已返回试卷”。

## 流程

1. 每个队列任务使用稳定的 `generation_request_id`。
2. `submit_exam` 返回并解析后，立即在服务端保存草稿；草稿不包含 AI 配置、API Key 或原始 HTTP 响应。
3. 队列任务模式下若校验失败，不执行整卷重试；失败任务记录可恢复草稿 id。
4. 用户点击“处理已返回试卷”后：
   - 执行现有确定性规范化和校验；
   - 只有当剩余错误全部属于 `figure_scene` 时，才逐题调用题图 scene 模型；
   - 再次执行同一套入库校验；
   - 按云端、本地、会话回退策略保存。
5. 保存成功或会话快照写入成功后删除恢复草稿。

## 导入侧「处理已返回结果」（与命题恢复共用闭环）

线下文件导入失败后，导入队列的「处理已返回结果」与命题侧走同一个共用修复函数
（`exam-generation.server.ts` 中 `repairStoredDraftParsedForRecovery`）：

1. 确定性 heal / 校验（与入库闸门一致）；
2. 剩余错误全部属于 `figure_scene` 时，逐题调用题图 scene 模型（携带 stage=figure 的已批准学习提示）并再次校验；非题图错误直接报错，不猜测修补；
3. 每次恢复**失败**写回草稿（`validation_failed`）并记录审计学习事件（outcome=observed，累积证据达阈值后可在设置中批准为提示策略，作用于后续导入与命题）；
4. 题图修复**成功**同样记录审计学习事件（outcome=repaired），随后走 `buildImportedExamSnapshotFromAiParsed` → `persistImportedBundle` 入库；
5. 仅入库失败时草稿保留为 `persistence_failed`，再次点击可直接重试入库，不重复调用模型。

## 安全边界

- 草稿默认有效期为 24 小时，过期后不能从错误日志猜测重建。
- 不自动修改非题图的题干、答案、选项、题量或分值。
- 题图专项模型只能生成结构化 `figure_scene`，仍须通过 Diagram Pack 校验。
- 恢复流程不会绕过正式题库的完整性校验。
- 同一次正常生成在云端保存失败后回退本地/会话时复用同一个已生成 bundle，不重新调用整卷模型。
