## 1. 主路径 vs 次路径（页面层次）

### 产品结论（推荐本机时）

| 层级 | 路径 | 文档依据 | 首屏角色 |
|------|------|----------|----------|
| **主路径** | 路径 A — 本机 MySQL 账号栈 | `account-and-machine-setup.md`：「推荐本机/离线」；`prd-account-mysql-local-scope.md`：方案 A +「MySQL 账号表就绪时优先本机登录」 | **首屏唯一主任务** |
| **次路径** | 路径 B — 云端 Supabase | `account-and-machine-setup.md` 路径 B；与 A「可并存」 | **默认不占首屏主位**；可跳过 |

### 推荐本机时，首屏主任务是什么

按路径 A 的既有步骤（文档原文语义，不新增动作）：

1. **填写并保存本机 MySQL 连接**（无预填主机/库名）
2. **执行建表**（含账号表；空库可自动种子运维）
3. （条件出现）**创建首个本机运维账号**——仅当建表后仍无账号、需手工 bootstrap 时为主操作；否则用**提示文案**说明「空库建表后通常已有默认运维」（与现卡 4 描述一致，与 `prd-account-three-portal.md`「首个运维」入口一致）
4. 去 `/login` 登录——**不在本页展开为第 N 步表单**；页头/就绪态用短提示即可（`account-and-machine-setup`：建表成功并刷新后黄条消失；现页已有「已就绪」绿条能力）

### 层次规则（交给实现）

- **页头**：短标题「配库」+ 至多一行副文案（UI 宪法 §3.3）。副文案须体现「先完成本机，或改用云端」，禁止多段技术说明。
- **主区默认展开**：仅主路径操作块（本机连接/测试/保存/建表；及条件性的首个运维表单）。
- **次路径**：整块「云端连接 + 云端建表」视为**可选次路径**，不得排在主路径之前抢主任务（解决「优先顺序层次不清」）。具体是「主区下方默认折叠的一组」还是「主区上方仅一句入口文案、点开再展开」——见文末选择题 Q1。
- **并存**：不删除次路径能力；登录优先仍以文档为准（本机账号表就绪 → 优先 MySQL）。

## 2. 折叠规则表

判定只分四类：**默认展开主操作 / 默认折叠高级 / 仅提示文案 / 状态侧栏**。

| 内容块（现状对应） | 归类 | 判定依据 | 说明（禁止发明新能力） |
|--------------------|------|----------|------------------------|
| 页头「配库」+ 一行副文案 | 默认展开主操作 | UI 宪法 §3.3 页头短标题；`account-and-machine-setup` 公开 `/setup` 为换机配库台 | 不堆步骤长文 |
| 黄条 `AccountSetupNotice`（需要先完成配库） | 仅提示文案 | `account-and-machine-setup`「界面提示」；现组件已存在 | **他页**：原因 + 简短步骤 +「前往配库」。**配库页内**：原因 + 一句「下一步」指向右侧主步骤；**不**再罗列与右侧卡片重复的步骤列表；可 `hideSetupLink` |
| 「已就绪」绿条 | 仅提示文案 | 现 `setup.tsx` 已有；`account-and-machine-setup` 建表成功提示消失 | 就绪判定须与文档「本机或云端任一条账号路径建表完成」一致，不以云端字段名误导（实现细节归工程，产品口径见 AC） |
| **本机数据库**：主机/端口/用户/密码/库名 + 创建库/测试/保存/执行建表 | 默认展开主操作 | `account-and-machine-setup` 路径 A 步 1–2；`prd-account-three-portal` 建表入口「本机 `/setup` … MySQL」；未登录允许填/保存/建表 | 主路径核心；层零用中文标签（已有），勿在默认层露表名/env |
| **本机「高级：建表脚本预览」**（加载/复制 SQL） | 默认折叠高级 | UI 宪法 §5 运维细节进「高级」；`account-and-machine-setup` 未登录允许「打包/复制 SQL」 | 能力保留在折叠内，不删 |
| **首个运维账号**表单（邮箱/密码/显示名 + 创建） | 默认展开主操作（**条件显示**） | `prd-account-three-portal`「首个运维」；`account-and-machine-setup` 空库种子 + 未登录允许 bootstrap；现面板仅在可 bootstrap 时给表单 | **可 bootstrap 时**展开主操作；已有账号或不可 bootstrap 时改为**仅提示文案**（说明原因），勿空表单占主位 |
| 云端连接四字段（账号服务地址 / 浏览器登录密钥 / 服务端密钥 / 云端数据库连接串）+ 保存 | 次路径主操作（相对主路径为次） | `account-and-machine-setup` 路径 B 步 1；标签已中文化（`RUNTIME_ENV_LOCAL_LABELS`） | 走云端时才是该路径的「默认展开」；走推荐本机时整段不进首屏主任务（见 Q1） |
| 「允许本页一键建表」勾选 | 次路径主操作（云端建表前提） | `account-and-machine-setup` 方式 A「一键迁移再设 ALLOW…」；现勾选文案已中文 | 仅服务路径 B；勿升格为本机主任务 |
| **云端「高级：配置项键名」**（`SUPABASE_*` / `DATABASE_URL` 等） | 默认折叠高级 | UI 宪法 §5 零技术词；现已 `<details>` | 保持折叠；默认层继续用中文标签 |
| **云端建表**：「执行初始化」按钮 | 次路径主操作 | `account-and-machine-setup` 路径 B 步 2 / 方式 A 云端「执行初始化」；未登录「条件允许时一键迁移」 | 与勾选/连接绑定；非本机主按钮 |
| **云端「高级：脚本预览」**（加载/复制） | 默认折叠高级 | UI 宪法 §5；`account-and-machine-setup` 可复制 SQL 到云端控制台 | 保持折叠 |
| 云端路径说明「本机方式可跳过」类句子 | 仅提示文案 | 现卡 1 描述已有等价语义 | 次路径入口旁一句即可，勿做成第三套步骤条 |
| 左栏「状态」+「重新检查」 | 状态侧栏 | 现结构；`account-and-machine-setup` 探测/刷新后提示消失 | 见 §3；缺项 detail 用短词（如「尚未完成」），长原因只放黄条，不做第二套步骤说明 |

### 折叠判定口诀（实现自检）

1. **主路径完成登录闭环所必需的操作** → 默认展开主操作  
2. **env 真名 / SQL 正文 / CLI / 表名** → 默认折叠高级（UI 宪法）  
3. **说明性、条件性、跳过指引、就绪/未就绪原因** → 仅提示文案  
4. **只读就绪信号** → 状态侧栏（不替代主区表单）

## 3. 状态侧栏：保留项与是否随路径切换

### 必须保留的就绪信号（与文档能力对齐）

文档要求用户能判断「能否登录 / 账号库是否就绪 / 本机是否已配 / 云端通道是否可用」。结合现侧栏与探测字段：

| 建议标签（层零中文） | 对应现状项 | 为何保留 | 路径相关性 |
|----------------------|------------|----------|------------|
| 可登录 | 「登录」 | `account-and-machine-setup`/`prd`：配库完成后去登录；探测含本机账号表就绪或云端 publishable | **共用**（任一路径就绪即可为真） |
| 账号库 | 「账号表」 | `prd` 账号权威；未建表业务拒绝 | **共用**（本机或云端表就绪） |
| 本机数据库 | 「本机数据库」 | 路径 A 连接是否已保存 | **主路径** |
| 账号管理 | 「账号管理」 | 云端需 Service Role；本机账号表就绪时探测已将 `serviceRoleReady` 视为 true | **共用语义**（勿暗示「只有云端才有账号管理」） |
| 云端数据库 | 「云端数据库」 | 路径 B 需要 `DATABASE_URL` | **次路径** |
| 本页一键建表 | 「本页一键建表」 | 仅云端 UI 迁移开关 | **次路径** |

### 是否随路径切换

**产品口径（本轮）：侧栏始终展示「共用 + 主路径 + 次路径」全量项，但须分组，不随路径卸载能力项。**

依据：文档写明「两条路径可并存」，卸载会掩盖并存态（例如本机已就绪仍可能后配云端）。

分组展示（信息架构，非新能力）：

1. **共用**：可登录、账号库、账号管理  
2. **本机**：本机数据库  
3. **云端（可选）**：云端数据库、本页一键建表  

主路径用户扫「共用 + 本机」即可验收；次路径用户再看「云端」组。  
**不**做「选了本机就隐藏云端状态」——除非用户在 Q2 改拍为「按意图过滤」。

### 明确不做

- 不新增状态项（如会话密钥、种子运维是否已写入等——文档未要求侧栏展示）  
- 侧栏不承载表单主操作（UI 宪法一屏一主任务：主操作在右栏）

## 4. 可验收清单（一眼对错）

**AC-IA-1 主任务**  
打开 `/setup`（推荐本机语境）：首屏主操作区首先是本机连接与建表，而不是云端四字段表单。云端块不得与本机块同级「1、2 在前、3、4 在后」抢优先级（除非 Q1 拍板维持文档编号视觉）。

**AC-IA-2 一次一主**  
首屏没有「四张对等编号卡并排争主」的观感；页头仅短标题 + ≤1 行副文案（UI 宪法）。

**AC-IA-3 折叠边界**  
默认可见层：无 `SUPABASE_*` / `DATABASE_URL` / `local_accounts` / `npm run …` 等技术词；上述仅出现在已折叠的「高级」内（UI 宪法 §5；与现高级块一致）。

**AC-IA-4 本机主操作齐全**  
未登录可完成：填/测/存本机连接、执行建表；高级内可加载/复制本机 SQL（`account-and-machine-setup` 未登录允许范围）。不预填主机/样例密钥。

**AC-IA-5 次路径可达且可跳过**  
不配云端也能走完主路径；需要云端时仍能保存云端连接、勾选允许后「执行初始化」，高级内可复制云端脚本（`account-and-machine-setup` 路径 B）。

**AC-IA-6 首个运维**  
空库建表后已有种子 → 卡区以提示为主，不强迫填表；仍无账号且允许 bootstrap → 表单为明确主操作（`prd` + 现面板行为）。

**AC-IA-7 侧栏分组**  
状态侧栏含 §3 六类信号，且「本机 / 云端（可选）」分组可辨；「重新检查」仍可用。

**AC-IA-8 并存与优先**  
本机账号表就绪后，可登录/账号库为就绪；不要求用户必须先配云端（`prd`/`account-and-machine-setup` 登录优先 MySQL）。

**AC-IA-9 大改闸门**  
实现前已列出将改文件范围并获同意（UI 宪法 `frontend_exec_confirm`）——本 PRD 不代替该确认。

## 5. 明确非目标（本轮不改）

- 不改登录协议、账号权威规则、建表 SQL、迁移脚本内容  
- 不改未登录允许/禁止的能力集合（只理顺呈现）  
- 不新增第三条账号路径、不删云端路径、不做双向同步  
- 不改门户、黄条业务逻辑（除非为与本页文案一致的**同义提示**，另单列）  
- 设置页「偏好」与配库的职责边界：设置保留试卷保存落点、习惯与更新；连接/建表以 `/setup` 为准，设置内仅一句跳转、不重复状态卡（见 `account-and-machine-setup.md`）  
- 不做视觉大改版 / 新色板 / 新组件体系（UI 宪法）
