# WBS：导入线下试卷 与「生成试卷」规则对齐 + 导入失败闭环

> **范围冻结依据**：[prd-offline-import-parity.md](./prd-offline-import-parity.md)（AC-1 ~ AC-6）
> **关联**：`src/lib/aiRuntime.shared.ts` · `src/lib/generationDraft.server.ts` · `src/lib/remoteImportJobsStorage.ts` · `src/lib/generationJobsStorage.ts` · `src/components/generation/GenerationJobQueues.tsx`
> **状态**：M1～M5 已实现并完成构建验证 · 2026-07-19

## 实施纪要（2026-07-19）

- 决策 1：学科无法归一时回退默认学科，并记录实际生效学科与回退标记。
- 决策 2：M4 纳入本轮，实现“处理已返回结果”的 24 小时草稿恢复。
- M1：新增模型解析回归测试；设置页明确按学科模型同时用于生成与导入。
- M2：文件上传导入复用统一导入队列，正文保存在当前浏览器，失败后可免重新上传重试。
- M3：导入校验复用命题的“学习提示 → 校验 → 最多重试一次 → 审计结果”闭环；失败详情支持查看原始日志。
- M4：模型已返回但校验/配图/保存失败时保留草稿，队列提供“处理已返回结果”。
- M5：相关 15 个测试文件、101 项测试通过；`npm run build` 通过。
- 边界：未针对具体模型 ID、题号或答案添加特殊分支；无效 `viewBox` 仅作为可选呈现字段忽略，几何事实校验仍保留。

## 4. 两处「待决策」的技术总监推荐默认

> 以下为推荐默认，供用户一键确认；用户也可另行指定，指定后请更新本文档「决策落地」栏。

### 决策一：学科归一化失败 — 静默回退 vs 阻断

**推荐默认：保留现状「静默回退默认学科」，不改为阻断；但要求补一条"低成本增强"——回退发生时把这一事实写入任务记录与学习事件，供审计。**

理由：
1. 三条导入入口的历史行为已经是"归一化失败 → 回退 `IMPORT_DEFAULTS.subject`"，改为阻断属于**破坏性变更**：会导致过去"不填/错填学科也能导入成功"的存量用法突然失败，与用户结论 2「导入应该像生成一样顺畅」的产品目标方向相反——用户要的是"失败要可诊断、可重试"，不是"更容易失败"。
2. 阻断需要新增一个强制交互步骤（要求用户手动确认/选择学科），这是一次 UI 行为变更，成本和范围超出本轮"补齐可观测性"的核心目标，且不在 PRD 范围内（PRD 非目标 5 明确排除大范围 UI 重构）。
3. 完全静默确实有隐蔽风险：用户以为某学科在用专属模型，实际因归一化失败悄悄换成了默认学科模型而不自知。低成本的缓解方式是"回退事实可查"而非"阻断交互"——把回退结果（原始 subjectId → 归一化结果 → 实际生效的 subjectId）写入 M2/M3 的任务记录与 M3 的 generation learning 事件里，用户在失败详情或成功提示里就能看到，不需要新增交互步骤，符合 M1/M3 的验收标准的自然延伸。
4. 目录数据（`data/remote-paper-catalog.json`）里维护者手填枚举外 `subjectId` 属于数据质量问题，建议按 PRD 第 4 节风险表的建议在目录校验脚本阶段加白名单检查，把问题挪到数据源头，而不是在运行时对用户加阻断。

**决策落地**：□ 同意默认（静默回退 + 记录审计） □ 改为阻断（需另行评估 UI 改动范围）

---

### 决策二：导入是否需要草稿恢复（`recoveryDraftId`）

**推荐默认：本轮不采纳（AC-5 判定为「否」），用 AC-2 的"复用已抽取正文重试"作为等效缓解；M4 保留为条件性里程碑，供后续按需插入排期。**

理由：
1. 命题生成与导入的"重新调用模型"成本结构不同：命题生成的草稿恢复价值在于避免**从零重新创作一整套原创题目+配图**（sunk cost 高，值得为此保存服务端草稿）；导入场景的 sunk cost 主要在**文件抽取/OCR 环节**，而 AC-2 已经明确要求"重试时复用已抽取正文"，唯一需要重新支付的成本只是**一次模型整理调用**，边际成本远低于命题场景，草稿恢复的 ROI 不如命题侧显著。
2. 不采纳可以避免本轮新增服务端 `data/generation-drafts/` 依赖在导入路径上的额外风险面（多实例部署/无持久磁盘环境下的草稿丢失问题，会从"命题侧已知限制"扩大为"命题+导入两处已知限制"），符合"先夯实核心缺口（AC-2/AC-3/AC-4）再评估是否需要更重的机制"的排期优先级。
3. 该决策不是不可逆的：PRD 第 5 节已明确"若后续采纳，应直接复用 `generationDraft.server.ts`，不新增另一套草稿格式"，M4 作为条件性里程碑保留在本 WBS 中，后续观察到"内容校验重试后仍频繁二次失败、用户对二次调用成本敏感"的真实反馈后，可随时插入排期，不会浪费前面里程碑的工作。

**决策落地**：□ 同意默认（本轮不采纳，M4 搁置） □ 采纳（本轮排入 M4，接受额外 2～3 人日与新增风险面）

## 5. 明确「不要做」（本轮红线，禁止出现在任何实现 PR 中）

1. **禁止 Interactions API 模型名硬编码**：任何新发现的模型不兼容场景，统一通过 `userFacingError.shared.ts` 的**通用错误特征识别**（HTTP 状态码 / 错误消息模式）+ 指向"设置 → 模型与接口"的提示路径处理；禁止在代码中出现针对具体模型 ID 的 `if (model === "...")` 式 special-case 判断，禁止把"绕过某个模型的已知问题"写成硬编码分支。
2. **禁止按题号/题型猜测 viewBox 或几何参数**：配图 `viewBox` 无效时的现有容错止步于"忽略无效值，回退到默认视窗做确定性渲染"，这是呈现层的兼容处理，**不允许**扩展为"根据题号/题型/答案分支反推或伪造几何数据"。Bug B 类问题的正确修复路径永远是「模型重新生成有效 scene」或「标记失败、用户可见可重试」，不是客户端猜测/编造几何输入。
3. 不改变现有队列"同一时间仅跑 1 条任务"的并发策略（PRD 非目标 2）。
4. 不在本轮新增/替换具体模型或云厂商适配（PRD 非目标 1）。
5. 不重做"网上试卷目录"数据来源/合规机制（PRD 非目标 4，遵循 `docs/remote-paper-catalog.md` 既有约定）。
