# 最终方案：内容流水线（课件 · 命题场景 · 网上导入）

> 状态：已落地（2026-08-01）· 无课件切片阻断命题 · 课件确认制 · 清单校验 · 仿照生成  
> 关联：`docs/remote-paper-catalog.md`、`data/curriculum/`、`src/config/curriculum-catalog.json`  
> 原则：**外源可采集，生效须确认；卷面可进库，正式须人审；场景决定绑什么课件，不静默改旧卷。**

---

## 0. 一句话

三条能力共用同一治理模型——**候选 → 提示/排队 → 确认 → 生效/入库 → 版本/状态保留**——分别服务「课件包」「生成试卷」「导入线下卷」。

| 能力 | 候选从哪来 | 确认谁做 | 生效后干什么 | 绝不做 |
|------|------------|----------|--------------|--------|
| 获取课件/课标 | 运维导入包 / 探测 | 运维确认切换 active | 命题只读 active；新卷绑 `curriculum_version` | 静默覆盖生效版、改写旧卷 |
| 生成试卷 | 教师选题干参数 | （命题本身） | 按场景读课件映射 + 提示词；**无 active 切片则阻断** | 场景空绑、降级假装用静态目录 |
| 网上获取试卷 | 合规清单（非公网整站爬） | 教师在「待确认」确认入库 | `staging`→`confirmed` 进库 | 应用内公网整卷爬、跳过待确认 |

## 1. 统一对象关系

```text
[课件包 curriculum_pack @ version]
        │ active 版
        ▼
[试卷场景 paper_kind] ──映射策略──► 选用哪类课件切片
        │
        ├─► 生成试卷 (/generate) ──落盘──► exam(curriculum_version, paper_kind)
        │
        └─► （可选）导入卷对齐场景标签

[远程试卷清单 catalog] ──队列──► exam(import_review_status=staging)
                                      │ 待确认人审
                                      ▼
                                 confirmed → 试卷库 / 班级可用
```

### 1.1 试卷场景 × 课件映射（产品口径）

| 场景组 | 示例 | 课件怎么绑 | 命题约束重心 |
|--------|------|------------|--------------|
| 常规考试 `regular` | 期末/月考 | **年级包 + 学年/学期 + 教材版本（人教版等）** | 单元/课时对齐 active 课件与所选出版社 |
| 升学考试 `entrance` | 中考/高考模拟 | **学段毕业包 + 升学大纲切片**（可与常规包并存） | 选拔覆盖，不强制单册课时 |
| 学科竞赛 `contest` | 竞赛培优 | **竞赛大纲包**（可独立版本轨） | 可超出课内细分范围 |

现状缺口：`paper_kind` 今日 mainly 影响提示词/学科过滤/标签，**尚未绑真实课件包**。本方案要求后续实现时按上表落映射，禁止「选了场景却仍只读静态 `generateCatalog` 硬编码」长期并存而不标明。

### 1.2 网上导入与课件的关系

- 导入卷**不强制**绑定课件包；优先保真原卷。
- 若目录条目带 `paper_kind` / `gradeId` / `subjectId`，入库后可**标注**对应场景与建议课件版本，供教师「仿照此卷再生成」时预填。
- 待确认审核可增加可选检查项：「场景/年级/学科与清单是否一致」（非阻断默认，机构可开严）。

## 2. 三条流水线（保留闸门）

### A. 获取课件（确认制 + 版本保留）

1. 发现/导入 → `pending`  
2. 系统提示 + 差分  
3. 确认 → `active`；旧版 `superseded`（不删）  
4. 命题只读 active；新卷写 `curriculum_version`  
5. 回滚 = 再确认把历史版标回 active  

### B. 生成试卷（场景驱动）

1. 选年级 / 学科 / **试卷场景** / 难度 / 范围  
2. 解析场景组 → 取对应 **active 课件切片**；**无切片则阻断**（前端不可提交、服务端拒绝），提示运维先确认生效课件或改选有切片的场景——禁止降级静默读静态 `generateCatalog`  
3. AI 命题 → 校验/配图 → 入库（非 staging；生成卷默认正式，失败走命题队列草稿）  
4. 卷面元数据：`paper_kind` + `curriculum_version`（有切片才可能落盘）  

### C. 网上获取 → 待确认（清单驱动）

1. 馆外合规采集 → `remote-paper-catalog.json`（或 HTTPS 合并）  
2. 「网上获取」筛选入队 → AI 结构化 → **staging**  
3. 「待确认」保真审核 → 确认入库 / 驳回  
4. 「已导入」与试卷库可见 confirmed  

**明确不做**：应用内对公网站整卷爬；跳过待确认自动进库；课件静默生效。

## 4. 优先级（最终）

按 **依赖顺序 + 风险闸门 + 已有能力复用** 排序。P0 不写新大功能，先锁口径与堵洞。

| 优先级 | 主题 | 交付 | 依赖 | 建议人日 | 验收要点 |
|--------|------|------|------|----------|----------|
| **P0** | 口径冻结与文档真相 | 本方案落盘；`remote-paper-catalog` / AGENTS 与「不爬公网、保留待确认、课件确认制」一致；生成页文案标明「场景尚未绑真实课件包」若未实现 | — | 0.5～1 | 三处文档无矛盾；空目录/无课件有诚实空态 |
| **P1** | 导入闸门打磨 | 清单校验（枚举白名单、缺正文）；待确认角标/筛选；网上队列失败详情对齐命题队列 | P0 | 2～4 | 坏清单 CI/脚本可拦；staging 不进 libraryList |
| **P2** | 课件包确认制 M1–M2 | 版本表/文件仓；导入候选；提示+差分；确认才 active；`generateCatalog` 读 active | P0 | 5～8 | 未确认前命题仍用旧版；确认后新卷带新 version；旧版可查 |
| **P3** | 场景 ↔ 课件映射 | `paper_kind` 组 → 课件切片策略；**无对应 active 切片则阻断命题**（不降级静态目录）；卷面写映射审计字段 | P2 | 3～5 | 常规=年级学期包；升学/竞赛走独立切片轨；无切片时生成入口不可提交并提示去确认课件 |
| **P4** | 导入↔生成联动 | 确认入库卷「一键仿照生成」预填场景/年级/学科；可选建议课件 version | P1+P3 | 2～3 | 从已导入卷跳到 generate 预填正确 |
| **P5** | 馆外采集样板（可选） | 授权 API/内网 → 清单的参考脚本（非公网爬虫） | P1 | 2～3 | README 强调授权；样板产出合法 JSON |
| **P6** | 体验增强 | 待确认批量确认；课件回滚 UI；旧卷「非当前课标」筛选徽标 | P2+P3 | 3～5 | 不改治理模型 |

### 优先级原则（决策用）

1. **先闸门、后自动化**：待确认 / 课件确认 先于爬虫样板与外源同步。  
2. **先生效真相、后场景智能**：课件 active 可读（P2）先于场景映射（P3）。  
3. **导入与生成共用元数据，不共用跳过审核**：生成卷直接正式；导入卷必须 staging。  
4. **公网爬虫永不进 P0–P3 主线**；仅 P5 可选且限授权源。

### 建议排期切片

- **Sprint A**：P0 + P1（进口径与导入可信）  
- **Sprint B**：P2（课件确认制）  
- **Sprint C**：P3 + P4（场景真正驱动命题，并打通导入仿照）  
- **Backlog**：P5、P6

## 5. 非目标（本最终方案明确排除）

1. 应用内公网整站/整卷爬虫产品化  
2. 删除「待确认」或导入默认 `confirmed`  
3. 课件更新静默切换 active  
4. 确认课件后批量改写已入库题干  
5. 用「试卷场景」文案冒充已绑定真实课件包；**无课件时警告降级继续命题**（已否决，改为阻断）
